# اختبارات مدارس المجد الأهلية

موقع ثابت (static) للوصول السريع إلى اختبارات وتجميعات **مركز المجد للقدرات والتحصيلي — مدارس المجد الأهلية**.

الموقع المنشور: <https://Ahmed-Yasser-El-Sharkawy.github.io/Almajd-Schools/>

## المجموعات

| المجموعة | العدد | المصدر | محمي بكلمة مرور |
| --- | ---: | --- | :---: |
| أقسام اللفظي الحديثة | 301 | `src/data/verbal-exams.json` | — |
| أقسام الكمي الحديثة | 118 | `src/data/quant-sections-exams.json` | نعم |
| تأسيس الكمي | 20 | `src/data/quant-foundation-exams.json` | نعم |
| بنوك أسئلة الكمي | 48 | `src/data/quant-releases-exams.json` | نعم |
| اختبارات لفظي محاكاة | 100 | `src/data/general-exams.json` | — |
| **الإجمالي** | **587** | | |

أقسام الكمي الحديثة (118 قسمًا، 1275 سؤالًا) مصدرها شيت Excel يُحوَّل أولًا إلى JSON
بالأمر `python -I scripts/sheet-to-json.py "<الشيت>.xlsx" "<الملف>.json"`؛ المحوّل
يُسقط عمود «رابط التعديل» فلا يصل إلى الموقع. ثم يقرأ `build-data` هذا الـ JSON.

مجموعات الكمي الثلاث تأتي من ملفات JSON المصدر خارج المستودع، وتُولَّد عبر
`npm run build-data`. نماذج التأسيس تحمل حقل `topic` (المهارة التي يعالجها كل
نموذج) وهو مفهرَس في البحث، فالطالب يجد «النموذج السابع» بكتابة «الكسور».

الإصدارات (48 إصدارًا، 2303 أسئلة) تأتي من ملفين مصدرين بمفاتيح عربية ولها محوّل مستقل
في `build-data.mjs`: يؤخذ 1-40 من ملف «1-42»، و41-48 من ملف «41-48» الذي أعاد
إعداد الإصدارين 41 و42. كل إصدار يحمل `questions` لأن العدد يختلف (48 غالبًا، و47
في الإصدار 38)، ويُعرض على البطاقة. ويحفظ الملف
`totalQuestions` المعلن في المصدر، و`validate-data.mjs` يرفض البناء إن لم يطابقه
مجموع الإصدارات.

## التقنيات

React 18 + Vite 5 + Tailwind CSS 3، بلا خادم وبلا قاعدة بيانات. جميع عمليات
البحث والتصفية تتم داخل المتصفح.

## الأوامر

```bash
npm install           # تثبيت الحزم
npm run dev           # خادم التطوير
npm run validate-data # التحقق من سلامة البيانات والروابط
npm run build         # التحقق من البيانات، بناء نسخة الإنتاج في dist/، ثم توليد صفحات SEO
npm run preview       # معاينة نسخة الإنتاج محليًا
npm run deploy        # بناء ونشر dist/ إلى فرع gh-pages
```

## بنية المشروع

```
src/
  components/   مكوّنات الواجهة (Header, Hero, ExamCard, Filters, ...)
  data/         بيانات الاختبارات بصيغة JSON
  lib/          طبقة المنطق: التطبيع العربي، البحث، التخزين المحلي، حالة الرابط
  assets/       شعارات المركز
scripts/
  build-data.mjs      توليد ملفات البيانات من المصادر الأصلية (بلا كلمات مرور)
  validate-data.mjs   التحقق من البيانات (npm run validate-data)
  prerender.mjs       توليد صفحة HTML لكل مجموعة + sitemap.xml + llms.txt (ضمن npm run build)
```

الفصل مقصود: ملفات `src/data` تُقرأ في `src/lib/exams.js` فقط، والمكوّنات لا
تتعامل مع JSON الخام إطلاقًا.

## تحديث البيانات

1. عدّل ملف JSON المناسب داخل `src/data/`، أو أعد توليد ملف اللفظي عبر
   `npm run build-data` بعد تحديث الملف المصدر.
2. شغّل `npm run validate-data` وتأكد من عدم وجود أخطاء.
3. شغّل `npm run build` ثم `npm run deploy`.

### تحديث «الأكثر تكرارًا» (أقسام اللفظي)

أرقام الأقسام الأكثر تكرارًا في ملف مستقل يُحرَّر يدويًا: **`src/data/verbal-priority.json`**.
هو منفصل عن `verbal-exams.json` لأن ذاك يُعاد توليده كاملًا عبر `build-data`، بينما
هذه القائمة يراجعها المدرب في مواعيدها الخاصة.

```json
{ "label": "الأكثر تكرارًا", "updated": "YYYY-MM-DD", "sections": [1, 2, 3, 5, 8] }
```

عدّل `sections` و`updated` ثم شغّل `npm run validate-data` — لا تعديل في الكود. ما يترتب على الملف:

| المكان | ما يظهر |
| --- | --- |
| البطاقة | شارة ذهبية «الأكثر تكرارًا» |
| أعلى القائمة | مفتاح «الأكثر تكرارًا فقط» بعدد الأقسام وتاريخ آخر تحديث، ويعمل مع البحث وبقية الفلاتر |
| الرابط | `verbal/?top=1` رابط مباشر قابل للمشاركة |
| وصف المجموعة والأسئلة الشائعة و`llms.txt` | العدد محسوب من البيانات، فلا يُكتب يدويًا في أي مكان |
| الصفحة المولَّدة `verbal/index.html` | كل قسم في القائمة مُعلَّم نصًّا |

الرقم المعروض هو عدد الأقسام **المنشورة فعلًا**. قائمة المدرب قد تسبق ملف الروابط
(قائمة 2026-10-23 تضم 302–310 ولا نماذج لها بعد): اترك هذه الأرقام في `sections`،
فـ`validate-data` يطبعها تحت «بلا نموذج منشور بعد» دون أن يفشل، وتُعلَّم تلقائيًا يوم
تُضاف نماذجها.

> **ملاحظة أمنية:** كلمة مرور النماذج موجودة في الملفات المصدر خارج المستودع
> فقط. `build-data.mjs` لا يكتبها إطلاقًا، بل يكتب العلامة `requiresPassword`
> وحدها؛ لأن أي شيء داخل `src/data/` يُحزَم في ملف الجافاسكريبت العام ويمكن
> قراءته من أدوات المطوّر. الواجهة تُعلِم الطالب أن النموذج محمي فقط، وكلمة
> المرور تُسلَّم داخل الفصل. و`validate-data.mjs` يرفض البناء إذا عادت كلمة
> المرور إلى ملفات البيانات.

## محركات البحث ومساعدات الذكاء الاصطناعي (SEO / GEO)

التطبيق يُرسم في المتصفح، فملف `index.html` وحده فارغ لمن لا يشغّل JavaScript،
وأغلب زواحف الذكاء الاصطناعي (GPTBot، ClaudeBot، PerplexityBot) لا تشغّله. لذلك
يشغّل `npm run build` في آخره `scripts/prerender.mjs`، فيكتب داخل `dist/`:

- `index.html`: تعريف الموقع، روابط المجموعات، والأسئلة الشائعة.
- `<المجموعة>/index.html` لكل مجموعة (`verbal/`، `quant-sections/`، ...): عنوان ووصف
  ورابط canonical خاص بها، وقائمة اختباراتها كلها كنص HTML.
- `404.html`، و`sitemap.xml` (تاريخ `lastmod` من آخر تعديل لملف البيانات في git)،
  و`llms.txt` (ملخّص Markdown للمساعدات الذكية).
- بيانات منظمة JSON-LD: `EducationalOrganization` و`WebSite` و`CollectionPage`
  و`ItemList` و`BreadcrumbList`، و`FAQPage` في الرئيسية.

كل النصوص (العناوين، الأوصاف، الأسئلة الشائعة) في `src/lib/seo.js` وحده، والأرقام
فيها محسوبة من البيانات؛ التطبيق والصفحات المولَّدة يقرآن الملف نفسه. لا تعدّل
النص بين علامتي `seo:start` و`seo:end` في `index.html`، فهو يُستبدل عند البناء.

لكل مجموعة مسار خاص (`/quant-sections/`)، والروابط القديمة بصيغة `?tab=` ما زالت تعمل.

بعد أول نشر: أضف الموقع في Google Search Console و Bing Webmaster Tools وأرسل
رابط `sitemap.xml`.

## النشر على GitHub Pages

الموقع يُنشر من فرع `gh-pages` عبر `npm run deploy`.
قيمة `base` في `vite.config.js` هي `/Almajd-Schools/` وهي مطابقة لاسم المستودع؛
تغيير اسم المستودع يستلزم تحديث هذه القيمة و`homepage` في `package.json`.
